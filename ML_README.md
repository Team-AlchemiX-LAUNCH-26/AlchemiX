# AlchemiX ML Pipeline & Training Guide

This guide details the end-to-end Machine Learning pipeline for **AlchemiX Phase 2**. The pipeline is designed with a strict **anti-leakage architecture** to ensure robust generalization to the live evaluation environment.

---

## 🌌 System Architecture

The intelligent routing system connects three distinct predictive models to evaluate the **True Cost** of a route path link-by-link:

```
                      Natural Language Request
                                 │
                                 ▼
                     Physics-Based Router (Dijkstra)
                                 │
                                 ▼
                 Sequentially Evaluate Path Links:
                  [ Link 1 ] ── [ Link 2 ] ── ...
                                 │
                 ┌───────────────┼───────────────┐
                 ▼               ▼               ▼
           Congestion       Trust Model     Targeting Model
             Model       (Dishonest Tel.)  (Chimera Attack)
                 └───────────────┬───────────────┘
                                 ▼
                         True Cost Formula
                                 │
                                 ▼
                    Final Annotated Route Output
```

## 🚀 Model Training Workflow

Training must follow the notebooks in chronological order. Skipping steps or ignoring splits will break the anti-leakage guards.

### Step 1: Exploratory Data Analysis (EDA)
*   **Notebook**: `notebooks/01_EDA.ipynb`
*   **Objective**: Analyze distributions, establish baseline target correlations (e.g., congestion load ratio correlation to latency is $\approx 0.69$), and investigate the class imbalance for Chimera attacks (only $\approx 8.2\%$ of links are jammed).

### Step 2: Data Preprocessing & Train/Test Split (Critical Step)
*   **Notebook**: `notebooks/02_Data_Preprocessing.ipynb`
*   **Objective**: Clean raw inputs (imputing missing values using KNNImputer, validating schemas) and execute the **80/20 train/test split**.
*   **Anti-Leakage Guard**: Splitting happens *before* feature engineering so that historical aggregates are computed from training rows only.
*   **Class Balance**: Incident splits are stratified on the target `jammed_flag`.

### Step 3: Feature Engineering
*   **Notebook**: `notebooks/03_Feature_Engineering.ipynb`
*   **Objective**: Generate row-wise engineered features and link-specific historical metrics.
*   **Transformations**:
    *   **Traffic**: Calculates interaction features (`load_units_x_ratio`, `load_ratio_sq`, `near_capacity`). Computes per-link historical statistics (`hist_mean_load_ratio`, `hist_std_load_ratio`, `hist_mean_load_units`) **only** from the training set, mapping them to the test set using a lookup merge.
    *   **Telemetry**: Derives `trust_score` target: 
        $$\text{trust\_score} = \frac{1}{1 + \frac{\max(0, \text{measured} - \text{self\_reported})}{\text{measured}}}$$
        Computes historical trust aggregates (`hist_mean_trust`, `hist_std_trust`).
    *   **Incident**: Extracts `traffic_percentage`, `high_traffic_share`, and computes `hist_attack_rate`. Note that `relative_traffic` is omitted to prevent global mean leakage.

### Step 4: Model Training, Tuning & Overfit Check
*   **Notebook**: `notebooks/04_Model_Training.ipynb`
*   **Objective**: Train estimators, optimize hyperparameters using Randomized Search, and evaluate train/test splits side-by-side.
*   **Metrics Tracked**:
    *   *Congestion & Trust (Regression)*: $R^2$ score, Mean Absolute Error (MAE), Root Mean Squared Error (RMSE).
    *   *Targeting (Classification)*: Precision, Recall, F1 Score, ROC-AUC.
*   **Class Imbalance Corrections**:
    *   `RandomForestClassifier` and `DecisionTreeClassifier` use `class_weight='balanced'`.
    *   `LGBMClassifier` uses `is_unbalance=True`.
    *   `XGBClassifier` initializes `scale_pos_weight` based on the negative-to-positive class ratio.
*   **Output**: Saves trained `.joblib` estimators, standard scaling preprocessors, and `model_metadata.json` to the `models/` directory.

### Step 5: Advanced Model Evaluation
*   **Notebook**: `notebooks/05_Model_Evaluation.ipynb`
*   **Objective**: Generate residual plots, calibration curves, ROC/Precision-Recall curves, and verify prediction ranges.

    }

## 🛡️ Go AI Agent Execution

The Go AI Agent (`ai/`) orchestrates inference at runtime:
1.  **Dijkstra Path Analysis**: Once a route is computed by the Phase 1 router, the path is translated into a sequence of sorted link IDs (e.g. `["Aegis", "Boreas", "Dawn"]` $\rightarrow$ `["Aegis-Boreas", "Boreas-Dawn"]`).
2.  **Sequential State Fetch**: Fetches live telemetry metrics for each link from the Live API Client (`ai/live_api.go`).
3.  **Microservice Prediction**: Sends sequential requests to the FastAPI microservice for each link.
4.  **True Cost Formula (`ai/cost.go`)**: Applies penalties to compute the True Cost:
    $$\text{True Cost} = \text{Physics Latency} + \text{Congestion Penalty} + \text{Trust Penalty} + \text{Targeting Penalty}$$
    *   **Trust Penalty**: $(1 - \text{Trust Score}) \times 50,000 \text{ ms}$
    *   **Targeting Penalty**: $\text{Jam Probability} \times 200,000 \text{ ms}$
    *   Qualitative safety labels (`safe`, `caution`, `danger`) are calculated based on the total AI penalty adjustment.
